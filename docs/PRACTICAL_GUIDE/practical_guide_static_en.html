Getting started

The dashboard — one studio, three workspaces

Where do I even start?

Everything in 02CartoLab is reachable from one window. The left rail switches between three workspaces: the Symbology Studio (Quick Style, 2.5D Buildings, Thematic Maps, Palette & Accessibility), the Layout Studio (Template Gallery, Map Sheet Studio, Grid + QPT Studio, 3D Isometric Stacker) and the Processing Hub, which lists every algorithm with a Run button. A collapsible drawer at the bottom holds system diagnostics and the run log.

Step by step

  1. Open the studio from Plugins ▸ 02CartoLab ▸ 02CartoLab Studio.
  2. The status chip in the header reports the plugin's own health; it reads ALL READY when every subsystem is available.
  3. Use the left rail to move between the Symbology Studio, the Layout Studio and the Processing Hub.
  4. Expand Diagnostics & Run Log at the bottom to see what each operation actually did — this is the first place to look when something does not happen.
  5. The Processing Hub doubles as documentation: every algorithm lists its own parameters and help text.

The result

Read the output. The dashboard is not a separate application from the Processing Toolbox — the same engines are exposed in both places. Use the dashboard for interactive, see-the-result work; use the Processing Hub (or the Model Builder) for anything that has to repeat, be scripted or run in a batch.

When it goes wrong

  • The window opens but stays empty — the plugin may still be loading; give it a moment and re-open.
  • A layer does not appear in the combos — the layer must be in the project, not merely visible in the canvas.
  • Nothing happens on Apply — open Diagnostics & Run Log; the reason is written there.
Symbology Studio

Quick Style — one-click thematic styling

How dense is İzmir, and can I publish that map without opening the symbology panel?

Quick Style turns any vector layer into a publication-ready choropleth or categorical map in a single action. Numeric fields are classified automatically, text fields become categories, and the colour palette comes from the plugin's own library (ColorBrewer plus the colour-blind-safe scientific ramps).

Step by step

  1. Open the 02CartoLab Studio from Plugins ▸ 02CartoLab ▸ 02CartoLab Studio and switch to the Symbology Studio workspace.
  2. In the Quick Style panel choose Layer: the İzmir district layer and Field: pop_density.
  3. Set Style as: Graduated (numeric), Classes: 5 and Break method: Geometric interval — the right choice for the long-tailed density distribution of a real city.
  4. Pick Palette: Viridis (sequential, colour-blind safe) and leave the white outline ticked.
  5. Press Apply Quick Style. The layer in the canvas is restyled immediately.
  6. Export the result with Export QML Style to reuse the exact symbology in another project.

The result

Read the output. The classes are equal-area in colour space but not in count. Compare the two ends of the ramp: with a geometric interval the darkest band covers the sprawling outer districts, the brightest band the compact central ones. Always read the legend, never the colour alone.

Symbology Studio

Monochrome print — photocopy-safe symbology

My journal prints in greyscale and photocopies the figure. Will the map still be readable?

With Monochrome print enabled, Quick Style replaces the colour ramp with black-and-white hatch and dot patterns that darken with the value. The legend keeps the numbers, so no information is lost when the figure is printed, photocopied or faxed.

Step by step

  1. Repeat the Quick Style workflow with the same layer, field and break method.
  2. Tick Monochrome print instead of choosing a colour palette.
  3. Apply the style and inspect the legend: each class now carries a distinct pattern, not just a shade of grey.
  4. Export the QML style so every figure in the manuscript uses the same pattern language.

The result

Read the output. Pattern density is the value channel. Light diagonal hatching = low, solid black = high. Check the darkest pattern against the smallest class: if two adjacent classes use patterns that read the same at final print size, reduce the number of classes.

Symbology Studio

2.5D building styling — extrusion that survives

Can I show Kadifekale's building massing as a real 3D-style extrusion instead of a pasted QML hack?

The 2.5D engine applies a native QGIS 25d renderer driven by a height or floor-count field. It writes the rule as a reusable expression, so the style can be re-applied to any layer with the same field, and it can be exported as a legend-friendly QML where each floor band is its own QGIS legend rule.

Step by step

  1. In the Symbology Studio open the 2.5D Buildings panel.
  2. Choose the layer and set Height field: height_m. If your data stores floors instead, set Height source: Floor count field and Floor height: 3.5 m.
  3. Pick a material preset — Warm Civic, Cool Slate, Urban Core Gold and eight more.
  4. Set Angle (45° is a good default), Height scale, and MAX_HEIGHT to clamp outliers.
  5. Enable Shadow and Wall shading so the massing reads as volume rather than flat colour.
  6. Apply the native 2.5D renderer, or switch Render mode to Per-floor colour bands to get one legend rule per storey.
  7. Export the QML style for reuse.

The result

Read the output. Compare the flat input with the result: the extrusion turns Kadifekale's street wall into a legible massing model. MAX_HEIGHT is the single most important control — without it one 300 m tower flattens every other building in the frame. Shadows only read if the building is big enough on screen: zoom in, don't shout.

When it goes wrong

  • Nothing extrudes — the height field is text, or contains NULLs; the expression uses coalesce() so NULL becomes 0.
  • The map is all roof colour — Wall shading is off, so no wall faces are drawn.
  • Floors are wrong — the floor height does not match your data; 3.5 m is the Turkish residential norm, offices are often 3.6–4.0 m.

Symbology Studio

Palette & Accessibility — CVD simulation and WCAG scoring

Will my map still be readable for a reader with deuteranopia, and does it pass the journal's contrast rule?

The Palette & Accessibility inspector lists every ramp in the plugin's library with live swatches, a five-mode colour-vision-deficiency simulation (normal, deuteranopia, protanopia, tritanopia, achromatopsia) and a WCAG 2.1 contrast score for each palette against the page.

Step by step

  1. Open Symbology Studio ▸ Palette & Accessibility and choose the layer you are styling.
  2. Filter Palette type: Sequential, Diverging or Qualitative, and tick Colour-blind safe only to see only the verified ramps.
  3. Select a palette and read the score line: it reports the palette family, the colour-blind safety badge and the WCAG contrast ratio.
  4. Use the CVD simulation strip to preview the same ramp under each deficiency mode.
  5. For a two-variable map, check that the two axes remain distinguishable in every mode, not just in normal vision.

The result

Read the output. A palette is colour-blind safe when the ramp keeps a lightness gradient as well as a hue gradient. A hue-only ramp collapses into indistinguishable bands under deuteranopia — the simulation strip makes that collapse visible before publication, not after review.

When it goes wrong

  • The contrast ratio looks low — a pale ramp on white paper fails WCAG for small text; darken the ramp or add a frame.
  • No palette appears — the filter is too restrictive; clear 'Colour-blind safe only' first.
Data Preparation

Normalization & rates — map the rate, not the count

Raw population just redraws the city footprint. How do I map dependency instead?

A choropleth of raw totals mostly shows where the city is built. This algorithm turns any field into a comparable rate: ratio per denominator, z-score, robust z-score (median/MAD), min-max, percentile rank, log, location quotient, winsorized min-max, decile rank, Tukey hinge rank, logistic, power and quantile-uniform scaling. The result is written as a new field and styled automatically.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Choropleth Normalization & Rates.
  2. Set Input to the district layer, Field to pop_total and Method to Rate (numerator / denominator).
  3. Choose Denominator: pop_15_64 — the working-age population — and Scale: 1000 for residents per 1 000 working-age people.
  4. Pick a sequential palette and 5 classes, then Run.
  5. Open the output attribute table: the new field holds the rate, and the layer already carries the matching graduated renderer.

The result

Read the output. A value above 1 means the neighbourhood depends on people outside its own working-age group. Values below 1 mean it has a demographic surplus. The rate is the map; the count is only context.

Classification Engine

Adaptive classification — GIC, Jenks, Head/Tail

How many classes does a skewed urban indicator actually need, and which break method fits it?

The classification engine implements seven break methods: Adaptive Geometric Interval (GIC), Head/Tail Breaks, Fisher-Jenks, standard deviation, Tukey box plot, maximum breaks and pretty round breaks. The output layer carries the class field and the matching renderer, so it drops straight into a layout.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Advanced Classification.
  2. Set Input to the district layer, Field to pop_density and Classes to 5.
  3. Choose Method: Adaptive Geometric Interval (GIC) — it follows the shape of a long-tailed distribution instead of forcing equal counts.
  4. Pick a palette and Run.
  5. Compare the result with Fisher-Jenks: run the algorithm again with METHOD = Fisher-Jenks and compare the class limits.

The result

Read the output. GIC produces ordered, readable intervals that follow the data's own spread; Jenks minimises within-class variance at the cost of irregular limits. If the two maps look the same, the distribution is not skewed enough for the choice to matter — and that is a useful result too.

Thematic Mapping

Bivariate choropleth — two variables, one honest map

Which İzmir neighbourhoods are both old and full of children — the ones that need care and schools at once?

A bivariate choropleth classifies two numeric variables into an N×N matrix and colours every polygon by the combination of its two class bands. The output carries a bivar_class field and a categorized renderer, and the plugin can export the matching legend matrix as vector geometry.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Bivariate Choropleth Map.
  2. Set Input to the district layer. FIELD_X: elderly_share (share aged 65+), FIELD_Y: child_share (share aged 0–14).
  3. Set CLASSES: 3 for a 3×3 matrix, METHOD: Quantile (Equal Count).
  4. Choose PALETTE_PRESET: Blue - Orange (Density & Economy) — or pick Custom Corner Colours to control all four corners.
  5. Run. The output is styled automatically with a categorized renderer on bivar_class.
  6. Run Export Bivariate 2D Legend Matrix with the same settings to obtain the diamond or square legend.

The result

Read the output. Read the matrix as two axes at once. The upper-right cell — high on both axes — is the hardest quadrant: an old population needing care and a young population needing schools in the same neighbourhoods. The legend is not decoration; without the axis labels the colours are meaningless.

Thematic Mapping

Bivariate legend matrix — export the key, not the picture

How do I get a publication-ready bivariate legend into my manuscript without redrawing it?

This algorithm writes the N×N colour matrix as a standalone vector polygon layer plus an HTML preview. Use DIAMOND for the classic bivariate diamond key, or squares. The geometry can be dropped straight into a print layout as a legend item.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Export Bivariate 2D Legend Matrix.
  2. Set CLASSES: 3 and choose the same PALETTE_PRESET as the map.
  3. Tick DIAMOND for a diamond key; leave CELL_SIZE at 30 mm for a print layout, or lower it for a slide.
  4. Set LABEL_X and LABEL_Y to the exact variable names used in the map caption.
  5. Run and choose the output location. The layer carries the matrix; OUTPUT_HTML gives a browser-ready preview.

The result

Read the output. The matrix is the legend of a bivariate map. If the labels in the matrix do not match the caption, the reader cannot decode the map. Generate the matrix from the same preset and class count as the map, every single time.

Thematic Mapping

Value-by-Alpha — fade the uncertain, don't hide it

My estimate is unreliable in some neighbourhoods. How do I show that without pretending the data is missing?

Value-by-Alpha separates the thematic variable from the reliability variable: hue carries the value, opacity carries the confidence. Low-confidence features fade instead of disappearing into a 'no data' colour — the map states its own uncertainty.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Value-by-Alpha (VbA) Map.
  2. Set FIELD_COLOUR to pop_density — the value you want the reader to see.
  3. Set FIELD_ALPHA to working_share — the share of the working-age population, used here as the reliability proxy.
  4. Set ALPHA_MIN: 64 and ALPHA_MAX: 255. Both are integers on a 0–255 opacity scale, where 0 is invisible and 255 fully opaque: 64 means the least reliable areas stay 25 % visible, 255 means the most reliable are solid.
  5. Choose a CVD-safe palette (Cividis) and 5 classes, then Run.
  6. Compare with the plain choropleth: the faded areas are exactly the places where the estimate should not be trusted.

The result

Read the output. A faded polygon is not missing data — it is uncertain data. That distinction is the entire point: a normal choropleth hides uncertainty behind a single grey, which reads as 'nothing here'. Keep the caption explicit about what the alpha variable means, or the reader will not know.

Thematic Mapping

Ridge map — turn any raster into relief

Can I show Kadifekale's terrain — or any continuous surface — as a ridge-line map instead of a flat hillshade?

The ridge engine samples a raster along parallel scanlines and draws each scanline as a profile, producing the stacked ridgelines of a Joy-Division chart. The source can be a DEM, a heat surface, a density raster or an accessibility index.

Step by step

  1. Reproject the raster to a projected CRS first — Raster ▸ Reproject Project Layer, or Processing ▸ GDAL ▸ Reproject. The ridge engine multiplies the raw elevation by the vertical exaggeration and adds it to the scanline position, so a DEM in degrees would throw the ridges thousands of degrees away. The plugin refuses a geographic CRS with an explanatory error.
  2. Open Processing Toolbox ▸ 02CartoLab ▸ Ridge Map.
  3. Set RASTER to the reprojected DEM and EXTENT to the area you want, in the DEM's own CRS (xmin,xmax,ymin,ymax).
  4. N_LINES: 120 gives a dense relief. SMOOTH: 2 removes single-cell noise.
  5. VERTICAL_SCALE is the exaggeration of the raw elevation. Derive it from the data: (map height × 0.3) ÷ maximum elevation makes the tallest ridge rise about a third of the frame. Change it and compare — too little flattens the relief, too much turns it into a cartoon.
  6. Set LINE_COLOR near-black, LINE_WIDTH: 0.28 and Run. The output is vector, so it can be styled and labelled in a layout.

The result

Read the output. The horizontal axis is distance, the vertical axis is the surface value. Dark ridges are high ground. Change VERTICAL_SCALE and watch the terrain change character — too little and it flattens, too much and it becomes a cartoon. The right value is the one that reveals structure without inventing it.

Where do people actually live inside these neighbourhoods, instead of just how many?

The dot-density engine seeds dots inside each polygon — one dot per N units of a count field — placing them away from edges and never inside holes. The same seed always produces the same map, so figures are reproducible across a report.

Read the output. The dot pattern carries spatial information the choropleth loses: it shows that a dense district is dense in one compact core rather than spread evenly. Never change the seed between figures of the same dataset — the same data must produce the same picture.

Proportional symbols — Flannery-compensated circles

Our values live at points, not polygons. How do I size the symbols so the reader's eye is not misled?

The proportional-symbol engine builds graduated point symbols with Flannery compensation: because people systematically under-estimate area differences, the symbol areas are scaled so that perceived size matches actual value. Symbols come in five shapes and the legend carries the nested values.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Proportional Symbols (Flannery).
  2. Set INPUT to a point layer — here the interior points of the district layer, each carrying pop_total.
  3. Set FIELD: pop_total, MAX_SIZE: 14.0 and MIN_SIZE: 2.0 (millimetres at layout scale).
  4. Choose SHAPE: Circle for area, Square or Diamond when the figure is printed in black and white.
  5. Leave FLANNERY ticked, set the fill and outline colours, then Run.
  6. Place the result in a layout: the legend is generated with the nested sample values.

The result

Read the output. The area of the symbol, not its radius, carries the value. Flannery compensation corrects the well-documented human bias that makes a circle that looks twice as big actually read as much more than double. Turn it off and the map quietly lies by about a third.

Thematic Mapping

Origin–Destination flow map — curved desire lines

How do people or goods move between places, and in which direction?

The flow engine converts an origin–destination table into curved, arrowed desire lines on the map. Width is proportional to volume, large flows are drawn first so small ones stay visible, and A→B and B→A are kept apart so a return trip never hides under the outward one.

Step by step

  1. Prepare a ZONES layer (polygons or points) with a unique id field, and an OD table with three fields: origin, destination and volume. The data/od_table.csv shipped with this guide is a working example.
  2. Open Processing Toolbox ▸ 02CartoLab ▸ Origin-Destination Flow Map.
  3. Set ZONES and ZONE_ID, then FLOWS with the ORIGIN, DEST and VOLUME field names.
  4. Tick DIRECTED to keep the arrowheads and separate opposite directions; set MIN_VOLUME to drop the noise, and TOP_N to keep only the strongest links.
  5. Tune CURVATURE (0.3 is a good default), MAX_WIDTH / MIN_WIDTH, and END_GAP so the line starts clear of the anchor.
  6. Run. The output is graduated by volume and drawn with large flows underneath.

The result

Read the output. The line width is the volume, the curvature is purely graphic, and the arrowhead is the direction. Read the map as a network of desire lines, not as a road map: crossing lines mean competing routes, not intersections. If a return flow is invisible, DIRECTED was probably off.

Cartogram Engine

Continuous-area cartogram — reshape by value

Where does İzmir's population really live, if the map is drawn so that area means people?

The cartogram engine continuously distorts every polygon so that its area is proportional to the chosen value, while shared borders stay contiguous and neighbourhoods stay neighbours. The result is a topology-preserving map in which geography is truthful but area carries the message.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Continuous-Area Cartogram (Diffusion).
  2. Set INPUT to a projected polygon layer — the engine measures areas in map units, so a geographic CRS is rejected. Use the district layer in EPSG:32635.
  3. Set FIELD: pop_total.
  4. MAX_ITERATIONS: 60 and MAX_ERROR: 5 (average area error in percent) control how long the diffusion runs.
  5. Choose PALETTE: Viridis and Run.
  6. Read the two outputs: ITERATIONS (rounds used) and RESIDUAL_ERROR (how far the areas still are from the target).

The result

Read the output. Compare the input and the result: the mountainous eastern districts shrink towards nothing because few people live there, while the compact central districts swell. The cartogram keeps the adjacency structure, so a district never floats away from its neighbours — that is what makes it readable where a Dorling cartogram is not.

Cartogram Engine

Dorling cartogram — circles that keep their place

Can I show totals without destroying the shape of the geography?

A Dorling cartogram replaces every polygon with a circle whose area is proportional to the value, positioned close to its original location by a force-directed relaxation. Districts with large values and small footprints stay visible instead of being squeezed out.

Step by step

  2. Set INPUT to the district layer and FIELD: pop_total.

  5. Choose PALETTE: Viridis and Run.
  6. Read the ROUNDS and RESIDUAL outputs to check how close the layout settled.

The result

Read the output. Use Dorling when the shape of the unit carries information — a coastline, a river, a border — and you still need to show totals. Use the continuous cartogram when the shape itself is the message. A Dorling circle says 'this much population, roughly here'; a distorted polygon says 'this much population, and this is what the land looks like under that pressure'.

Hexbin aggregation — density without overplotting

Too many points, too little map. How do I aggregate them honestly?

The hexbin engine bins a point layer into a pointy-top hexagonal grid and aggregates a weight per cell — count, sum or mean. Hexagons tile the plane with no gaps, which keeps the density surface continuous while removing the overplotting that hides real structure.

Step by step

  2. Set INPUT to a point layer — the interior points of the district layer, each carrying pop_total.
  3. Set CELL_SIZE: 1500 (hexagon edge in map units — the mesh size of your analysis) and WEIGHT: pop_total.
  4. Choose STAT: Sum of weight to accumulate population per cell, or Mean of weight for an average.
  5. Choose CLASSIFIER: Quantile and CLASSES: 5, then a palette, and Run.
  6. The output carries hex_count, hex_sum and hex_mean so you can re-classify without recomputing.

The result

Read the output. A hexagonal mesh removes the false precision of small administrative units: the map shows a smooth surface rather than a patchwork of arbitrary boundaries. Choose the cell size from your question — 1.5 km cells answer neighbourhood questions, 500 m cells answer street-level ones.

Labeling

Visual-centre label points — labels that stay inside the shape

Why do my district names keep falling off the districts?

Centroid labels drift outside concave shapes. The label-point engine computes the pole of inaccessibility for every polygon — the point furthest from the polygon edge, which is guaranteed to lie inside — and writes it as a new point layer you can join to your label layer.

Step by step

  1. Open Processing Toolbox ▸ 02CartoLab ▸ Visual-Center Label Points.
  2. Set INPUT to the polygon layer and PRECISION: 1.0 (the search tolerance in map units; lower is finer).
  3. Run. The output is a point layer with one anchor per polygon.
  4. Join the anchor layer to your label layer on the polygon id.
  5. In the label layer set the anchor mode to the joined point, and add a callout line for the labels that would still overlap.

The result

Read the output. The anchor is the visually strongest position inside the shape — the same principle that puts a logo in the optical centre of a triangle. For long, thin or crescent-shaped districts it is the difference between a legible label and one that hangs in the sea.
